# Changelog

## 0.1.0 (unreleased)

- Changed: on the Logs tab the product filter is now a "Ping products" dropdown, like the shelf's. It lists the products in the current result with their line counts, Ping products (PingOne, PingFederate, Ping Gateway and the Privilege family) apart from other services (the AI-DEMO2 banking MCP server, LLM proxy and so on), and uses the lab's own product names, so the Privilege sources no longer show as raw ids such as `pgateway`.
- Fixed: `docker compose up` always started in Mock because the image sets `MODE=mock`. Compose now passes `MODE: ${OBS_MODE:-}`, so with `OBS_MODE` unset the lab starts in Real when Real is configured and in Mock otherwise.
- Changed: the port-forward hints show `<your-context>` and `<your-namespace>` unless `OBS_KUBE_CONTEXT` and `OBS_KUBE_NAMESPACE` are set (validated names; anything else keeps the placeholder).

- Added: the Pipeline tab shows the paths that now exist besides the mock Loki path: Privilege hosted gateway and console to the Privilege SIEM export and the Privilege logs bridge (decisions, AI Guard, approvals) into `ping-siem-events-v2`; a Vector collector on local Docker reading PingFederate, PingGateway and the Privilege agent gateway into `ping-logs-*` (noise tagged, secrets masked); the PingOne webhook subscription through pingone-events-LAB into `ping-logs-pingone`; Elasticsearch to Kibana; and this lab reading the Privilege index through the loopback forwarder and linking into Kibana. 11 new boxes and 14 new Simulate steps (21 and 21); each new box has a one-line description and its honesty label (measured live 2026-11-08, or for PingOne: being switched on, not measured yet).
- Changed: the Searches tab PingOne service select uses the `ping_component` values the Elasticsearch pipeline writes (sso, mfa, davinci, authorize, protect, verify, credentials, directory, governance, provisioning, admin-config, other) with readable labels.

- Added: more Kibana links in the **Privilege logs in Kibana** panel, all on the `PRIVILEGE_KIBANA_URL` origin: the Privilege overview dashboard, the Ping logs (all products) dashboard, Discover on the `ping-logs` data view (last 30 days), Security detection rules, and the Detection rule monitoring dashboard. The first two links are now labelled Privilege logs dashboard and Discover on Privilege logs.
- Fixed: the **Denials and holds** query counted AI Guard denials and could count a hold more than once. It is now policy decisions only (`Index : "policy-decision-log" and privilege.decision : ("deny" or "hitl")`); its note points to the AI Guard query and says the overview dashboard counts each hold once by request id.

- Measured: accepted A2A calls are shipped to OpenSearch (Received HTTP request documents), so an A2A allow is visible there although the gateway pod log has no allow line; a document means accepted and handed on, not succeeded.

- Added: the HITL service as a fifteenth source (receipt verification), the Ping Gateway authorize decision lines (DECISION PERMIT obligation=hitl, INDETERMINATE HITL challenge minted), and measured PingFederate audit and admin-api and Gateway access-audit lines now on stdout (AI-DEMO2 #3437). Alloy ships ten containers. All measured 2026-11-08.
- Fixed: the HITL notes said a correlation id joins the Gateway lines to the HITL service. Checked by searching every local container for the ids: the challenge id joins the API server, Gateway and HITL service; the correlation id and trace id are in the HITL service only; none of them reach the hosted gateway log or OpenSearch.

- Added: the weather MCP server as a fourteenth source (start-up, place lookup and tool-error lines, one JSON object per line, measured 2026-11-08) and Alloy ships it in Real mode. Measured and recorded, not added as sources: Brave and audit print nothing per call; HITL prints only start-up lines (its routes need a shared secret). New fact: a trace id did not join lines across these services (banking server trace ids stay in its own log; all 360 Jaeger traces of the last two hours had one service).
- Changed: the Mock Privilege SIEM sample now has the document shapes measured on 2026-11-08 by the privilege-logging-LAB session (audit-log, proxy-audit-log, policy-decision-log, aiguard-log), with the value domains seen (Decision allow, deny or hitl; Event policy_decision, policy_approval_required or policy_approval_released; PrincipalKind User or NonHumanIdentity; AgentKey missing or empty on about half). agent-approval-log stays UNVERIFIED. `@timestamp` confirmed as the time field. In Real mode a line's level now follows the document's own Level (INFO, WARNING, ERROR), and a deny or a hold shows as warn.
- Added: a **Privilege logs in Kibana** panel on the Products tab: Dashboard and Discover links, five saved searches, and seven ready-made KQL queries (runtime, console, decisions, runtime with a decision, denials and holds, AI Guard, gateway HTTP), each with a Copy button and a Run in Discover link, plus the field notes and the tunnel command. All links come from `PRIVILEGE_KIBANA_URL` (default `http://localhost:5601`); the lab never calls Kibana. Tests pin each link and that each query decodes back exactly.
- Added: the Privilege SIEM as a thirteenth source and a second Real source. Real reads the Elasticsearch index `ping-siem-events-v2` read-only (one `POST /<index>/_search` to a loopback origin, no redirects, size cap, key never returned or logged, secret-looking fields scrubbed again), each line labelled `kind` (console or runtime) and `index`, with a look-back of up to 30 days. Needs `PRIVILEGE_SIEM_URL` and an owner-created read key `PRIVILEGE_SIEM_READ_APIKEY`; Mock holds a placeholder-only sample (shape UNVERIFIED). Alerts treat an unset source as silent, not as an error.
- Added: an **Open in Kibana (Privilege logs)** link and its port-forward command on every Privilege product (`PRIVILEGE_KIBANA_URL`, default `http://localhost:5601`).
- Fixed: Alloy strips terminal colour codes (ESC sequences) before storing a line. The pattern is a capture group because stage.replace changes only what a group matched (the first version, without one, stored lines unchanged). The Ping Gateway and the banking MCP server colour their output, so in Real mode their lines showed as escape text.
- Added: five sources, each sampled from the running service on 2026-11-08: the hosted gateway's OpenSearch events (seven kinds of JSON document, field names measured), the Prompt-Guard sidecar's verdict lines, the banking MCP server (header line plus indented context lines carrying the trace id), the LLM proxy's routing lines, and the authz server (each decision printed twice, readable and JSON). Real PingFederate (server log on stdout, half DEBUG) and Ping Gateway (a repeating router ERROR) lines added to the two existing products. Not added: weather, Brave, audit, HITL, agent-service (start-up lines only).
- Added: Alloy ships the five local services in Real mode (exact container names), with a rate limit on the whole pipeline; the compose test pins the names and the limit stage.
- Added: a seventh source, the Privilege hosted gateway (`agentless-mcpgw`), with six line shapes measured on 2026-11-08: who is calling, which app, forwarded to the backend (the only sign of an allowed call), refused by policy (level info), policy-evaluation noise, and a guardrail block. Ids and hostnames are placeholders.
- Added: click a log line to open it. The detail shows the exact time, labels, the whole message, the fields found in it (JSON or key=value), what kind of line it is with its honesty label, and a trace button. Closed rows look as before. Keyboard: Enter or Space. Selecting text in a line does not collapse it.
- Added: Privilege agent gateway (`ping-mcpgw`) as a sixth source (lab PR #1).
- Changed: the agent gateway mock writes the two rejection messages as a pair from one request (measured: 22,022 of 22,192 invalid-token lines directly follow a missing-header line), not as two independent streams. Added: the four `[SERVER]` request lines (Incoming request, User-Agent, Remote Addr, Content-Type) to the mock and to the Alloy filter; a refused request to an MCP app path writes no line (measured).
- Added: Privilege logs in the own stack: node sensor and MCP gateway from stdout, agent gateway from AI-DEMO2's log volume (optional `docker-compose.privilege.yml`, read-only, tail from end, three message families kept). Alloy drops container history older than 15 minutes (a restart otherwise made Loki reject the replay).
- Added: own log stack (compose profile `stack`: Loki 3.3.2 + Alloy v1.19.2 sharing the lab's network namespace, nothing extra published) and a Playwright browser driver in Docker (profile `drive`) that visits labs through the lab-proxy so Alloy ships real access-log lines. See README.

- Core: seeded mock log stream for PingOne, PingFederate and Ping Gateway (replayed relative to now), LogQL-lite with literal-only regex operators, three alert rules (burst, ratio with a traffic floor, silence), per-workspace incidents and relabel switch, runtime Mock/Real toggle, read-only loopback Loki client for Real, W3C traceparent on every hop, doctor that replays every scenario.
- Web: Logs, Products, Pipeline (diagram-studio/1 data), Label lab, Alerts, Talk track; presenter mode.
- Port 7800 (one port, from the shelf allocator; the first draft used 7720-7729, which meridian-a2a-hop already owns). Catalog id D123 (chosen by the owner 2026-11-07; D122 belongs to a2a-lab).
